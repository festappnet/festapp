## 1. Zadání (Julie, e-mail)

- Každý záchod má **identifikační číslo** (např. „05“), vylepené na dveřích.
- Účastník otevře v aplikaci záložku úklidu, **vybere toaletu podle čísla** a

  1. Nedostatek toaletního papíru → **žlutá**
  2. Nedostatek hygienických potřeb → **oranžová**
  3. Totální znečištění → **červená** (ideálně se symbolem ☣️)
- Volitelná **poznámka od ohlašovatele**.
- Úklid vidí **seznam záchodů s ikonami**; bez problému **zelená**, po ohlášení
  barva podle typu. Úklid dostane **upozornění** a vyšle výjezd.
- „Adminský“ přístup k hlášením mají mít **Julie + 2 hlavní pomocníci**.
- Bonus: **interaktivní mapka** s barevnými ikonami záchodů.

## 2. Koncept — mapování na existující architekturu

Vše potřebné v aplikaci už existuje, feature je hlavně slepení hotových
mechanismů:

| Potřeba | Existující mechanismus |
|---|---|
| Záchody s číslem a polohou | Řádky v `places` (occasion FK, jsonb souřadnice, `icon`); kategorie přes `place_types` (code `toilet`) → mapa je umí filtrovat chipy už dnes |
| „Julie + 2 pomocníci“ | **Nové per-occasion oprávnění `is_cleaning_crew`** na `occasion_users` — přesný precedent je pár `is_editor_order`/`is_editor_order_view` („malá podmnožina uživatelů dostane jedno admin pod-právo“). **Rozhodnuto 2026-07-10** místo původně zvažované uživatelské skupiny (`user_group_info` type `cleaning`): oprávnění se uděluje ve stávající admin záložce Uživatelé, žádná skupina bokem. |
| Push notifikace četě | Insert do `log_notifications` s `to = [uuid…]` → DB trigger `push_log_notifications` → edge fn `notify` → OneSignal (external_id = user id). Žádná nová infrastruktura |
| Zapnutí per occasion | Feature flag pattern (`FeatureConstants`, `FeatureService.isFeatureEnabled`), viz `counseling` jako čerstvý precedent |
| Vzor „účastník odešle hlášení přes RPC“ | `event_feedback` (`submit_event_feedback`) — RPC se SECURITY DEFINER, envelope `{code, message, data}` |
| Admin seznam s refreshem | Vzor `OrdersContent` / crew view s ručním reloadem; realtime v repu neexistuje → polling |

**Co je nové:** tabulka `cleaning_reports`, 3–4 SQL funkce, stránka „Úklid“,
obarvení pinů na mapě (dnes je barva pinu jedna theme hodnota —
`ThemeConfig.mapPinColor` v `map_location_pin_helper.dart`).

### Stavový model záchodu

Záchod nemá vlastní stavový sloupec — **stav se odvozuje z otevřených
hlášení**: závažnost `paper(1) < hygiene(2) < contamination(3)`, barva záchodu
= nejvyšší závažnost otevřeného hlášení, žádné otevřené = zelená. „Uklizeno“
= vyřešení všech otevřených hlášení daného záchodu najednou (četa řeší místo,
ne jednotlivé řádky).

## 3. Databáze

### 3.1 Tabulka (do `database/tables/tables.sql`, konvence repa)

```sql
create table if not exists public.cleaning_reports (
  id           bigint generated by default as identity primary key,
  occasion     bigint not null references public.occasions(id),
  place        bigint not null references public.places(id),
  problem_type text   not null,          -- 'paper' | 'hygiene' | 'contamination'
  note         text,
  created_by   uuid default auth.uid(),
  created_at   timestamptz default now(),
  updated_at   timestamptz not null default now(),
  resolved_by  uuid,
  resolved_at  timestamptz,
  data         jsonb
);
```

- `moddatetime` trigger doplnit do `setup_triggers`
  (`database/functions/seed/triggers.sql`).
- **RLS**: žádný přímý client-side insert/update — všechny zápisy přes
  SECURITY DEFINER RPC. SELECT policy jen pro editory
  (`get_is_editor_view_on_occasion`); četa čte přes RPC.
- **Nový sloupec oprávnění** na `occasion_users`:
  `is_cleaning_crew boolean not null default false` (vedle `is_editor`,
  `is_editor_order`, …). Na live se přidá `ALTER TABLE … ADD COLUMN IF NOT
  EXISTS` v migraci.

### 3.2 SQL funkce (`database/functions/cleaning/`, jedna na soubor)

Všechny `SECURITY DEFINER`, `SET search_path = public, extensions`, envelope
`{code, message, data}`, chybové kódy v envelope (vzor
`create_unit_and_assign_manager`).

1. **`get_is_cleaning_crew_on_occasion(oc bigint) returns boolean`** — helper
   (do `user_permissions/`, vzor `get_is_editor_order_on_occasion`):
   `occasion_users.is_cleaning_crew` pro `auth.uid()` na dané occasion, NEBO
   `get_is_editor_on_occasion(oc)` (editoři/admini mají právo implicitně).

2. **`report_cleaning_issue(place_id bigint, problem_type text, note text)`**
   — jádro featury:
   - validace: přihlášený uživatel; place existuje, patří occasion, má typ
     `toilet`; `problem_type` ∈ povolené hodnoty; feature `cleaning` zapnutá
     (čtení `occasions.features`, vzor `get_is_counseling_enabled_on_occasion`).
   - **dedup**: existuje-li otevřené hlášení stejného `(place, problem_type)`,
     nevkládat duplikát a **neposílat další notifikaci**; vrátit 200 s
     `data.duplicate=true` (účastníkovi UI řekne „už nahlášeno, četa o tom ví“).
     Poznámku z duplikátu přilepit do `data` existujícího řádku, ať se neztratí.
   - **rate limit**: max ~5 hlášení od jednoho uživatele za 15 minut → kód 429
     (ochrana proti spamu/vtipálkům).
   - insert hlášení + insert `log_notifications` řádku:
     `to` = uuid uživatelů s `is_cleaning_crew` na occasion
     (`select "user" from occasion_users where occasion=oc and
     is_cleaning_crew`), `heading` = `„WC 05 — Totální
     znečištění ☣️“`, `content` = poznámka (nebo název typu). Emoji ☣️ projde
     OneSignalem bez úprav.

3. **`get_cleaning_status(oc bigint)`** — veřejné (každý přihlášený): seznam
   záchodů occasion (`places` type `toilet`, ne-hidden) + odvozený stav
   (`green|paper|hygiene|contamination`) a čas posledního hlášení. Pohání
   barevný seznam účastníka i obarvení mapy. Bez poznámek a jmen ohlašovatelů.

4. **`get_cleaning_reports(oc bigint)`** — jen četa
   (`get_is_cleaning_crew_on_occasion`): otevřená hlášení s poznámkami, časy,
   ohlašovatelem; volitelně i historie vyřešených (parametr).

5. **`resolve_cleaning_place(place_id bigint)`** — jen četa: nastaví
   `resolved_by/resolved_at` všem otevřeným hlášením záchodu → záchod zezelená.

### 3.3 DB testy (`database/tests/cleaning/`)

## 5. Notifikace — detail

- Odeslání řeší RPC (3.2/2) insertem do `log_notifications` — client-side
  `DbNews.sendGroupNotification` se nepoužije (účastník nemá editor práva na
  insert, proto to musí udělat SECURITY DEFINER funkce).
- **Deep link z notifikace (rozhodnuto, Q6)**: edge fn `notify` dnes staví
  `web_url` napevno na `/#/<occasion>/news`. Rozšíří se: `notify/index.ts`
  čte volitelný `record.data.path` a použije ho místo `news`; když chybí,
  chování je beze změny (stávající notifikace nedotčené). RPC
  `report_cleaning_issue` vloží do `log_notifications.data`
  `{"path": "cleaning"}` → klik na push otevře rovnou stránku Úklid.
  Pozn.: `log_notifications` sloupec `data` dnes nemá — přidat
  `data jsonb` (nullable) do `tables.sql` + migrace, trigger posílá celý
  řádek, takže edge fn ho uvidí automaticky.

## 6. Fáze implementace

Každá fáze samostatně testovatelná; pořadí minimalizuje rozdělanost.

1. **DB základ** — tabulka + trigger + RLS, place_type `toilet`, 5 SQL funkcí,
   DB testy. Ověření: `node web_client/scripts/run_db_tests.js …` na lokální
   PG17 (:55432).
2. **Flutter data + feature** — `FeatureConstants.cleaning`, `DbCleaning`,
   modely, `CleaningStrings` (cs+en).
3. **Účastnické UI** — `CleaningPage` (+ `:id` deep-link routa) + report
   dialog + položka „Úklid“ na profilové stránce; feature gating.
4. **Pohled čety + notifikační deep link** — poznámky/časy, „Uklizeno“,
   polling; úprava `supabase/functions/notify/index.ts` (čtení
   `record.data.path`, fallback `news`). Ruční E2E: nahlásit z druhého účtu →
   push dorazí uživatelům s `is_cleaning_crew` → klik otevře Úklid → resolve
   → zelená.
5. **Mapa** — barevné piny, popup s hlášením, prolink z dlaždic.
6. **Nasazení a provoz** — SQL na live **před** klientem (management API,
   vzor counseling split); deploy upravené edge fn `notify` (`supabase
   functions deploy notify`, viz `docs/backend/edge_functions.md`) — bezpečné
   předem díky fallbacku na `news`; bump `VERSION`, commit `<verze>; cleaning
   service…`, `deploy_direct.sh` (csmostrava standard, žádný git push).
   Provozní setup v adminu: založit places s typem `toilet`, **title =
   dvouciferné číslo ze samolepky ve tvaru „WC 05“** (dlaždice i seznamy řadí
   podle title, proto nuly zleva) a polohou; v záložce Uživatelé zaškrtnout
   `is_cleaning_crew` Julii + 2 pomocníkům; zapnout featuru. Vyrobit
   samolepky s čísly (viz Q5 — bez QR).
