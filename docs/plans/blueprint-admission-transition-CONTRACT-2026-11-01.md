# Seating transition transport contract - revision 1

All public RPCs use named `p_*` arguments below. Read/preview returns `{code:200,data:{...}}`; mutation returns the existing ClientCommandTransport receipt envelope, whose `data` contains `{transitionId,context}` or `{transitionIds,context}`. Typed terminal rejection is the normal rejected receipt with `data.reason` and `data.blockers`. UUID and exact request must be retained for replay. SQL permissions always derive from stored scope.

- `get_seating_workspace(p_occasion bigint,p_blueprint bigint default null)`: safe entry/configuration context `{blueprintId,plans:[{id,title,valid}],forms:[{id,title,link,transitionId,activeBlueprintId,canStart,reason}],transitions:[{id,formId,blueprintId,state,revision}],capabilities:{configure,readHolders,assign},status:'choose_plan'|'repair_plan'|'organizer_managed'|'published'|'no_source'}`. Plan selection is explicit if multiple. No holder data.
- `start_seating_configuration(p_form bigint,p_blueprint bigint,p_command_id uuid)`: explicit choose/start, same private lifecycle owner used by occasion enable. Returns receipt with `transitionId`.
- `get_seating_transition_context(p_transition uuid,p_search text default '',p_category text default null,p_after bigint default null,p_limit integer default 50)`: data `{transitionId,blueprintId,layoutRevision,state,revision,cohort:[{id,formId,revision}],capabilities:{configure,readHolders,assign},counts:{unassigned,assigned,standing,blocked,waiting,offered},items:[{ticketId,admissionItemId,orderId,formId,ticketSymbol,orderSymbol,holder,productId,productTitle,spotId,category,reason}],nextCursor,compatibility:[{productId,productTitle,admissions,seats,standing,reason}],seats:[{id,title,productId,available,reason,unitSpotIds}],publicationAvailable}`. Counts always whole cohort, private items only order readers; seats contain no holder/hold secrets. Cursor is ticketId, max 200.
- `preview_ticket_seat_assignment(p_transition uuid,p_mappings jsonb)`: data `{fingerprint,revisions:[{id,revision}],mappings:[{ticketId,admissionItemId,expectedSpotId,targetSpotId,formId,productId}],blockers:[{reason,ticketId?,spotId?}],layoutRevision}`. Mappings request exact four fields `{ticketId:101,admissionItemId:201,expectedSpotId:null,targetSpotId:301}`, release target null. Max min(256, existing order mutation policy hard cap); no implicit pairing. Review enabled only if blockers empty.
- `set_ticket_seat_assignments(p_transition uuid,p_mappings jsonb,p_fingerprint text,p_command_id uuid)`: frozen reviewed mappings + fingerprint. Receipt includes refreshed context. No financial mutation, QR replacement or mail.
- `preview_seating_publication(p_transition uuid)`: data `{fingerprint,transitionIds:[uuid],revisions:[{id,revision}],forms:[{id,title,participantCapacity,blueprintId,capacity,available}],blockers:[{reason,formId?,ticketId?}],catalog:[...],layoutRevision}`. Optional publication; waiting does not prevent assignment success. Review confirms changed sales scope explicitly.
- `publish_seating_transitions(p_transition uuid,p_transition_ids uuid[],p_fingerprint text,p_command_id uuid)`: entire exact cohort or typed conflict. Retains form open/schedules.
- `cancel_seating_configuration(p_transition uuid,p_expected_revision bigint,p_command_id uuid)`: only empty configurations; closing workspace never calls cancel.

Reasons follow plan section 9. Categories are `unassigned`, `assigned`, `standing`, `blocked`, `waiting`, `offered`. `publicationAvailable` indicates configure capability, not readiness. All-assigned means unassigned=0 AND blocked=0; waiting/offered shown separately. Saved plan only: host must resolve Save/Discard/Cancel before workspace actions. Geometry package remains untouched. `get_blueprint_for_edit(occasion_link text,p_blueprint_id bigint)` is explicit-target reader; one-argument adapter selects only sole unambiguous plan.

Workspace source actions fail closed on `forms.canStart`. Existing active public plans without transition rows report workspace status `published`; the organizer workspace never offers to retrofit them.

Configuration start/cancel/publication receipts store aggregate context with `items:[]`, even for operators who currently have holder access. A later loss of holder-read authority therefore cannot expose old private worklist rows through an otherwise authorized configuration replay. Assignment receipts retain their exact mappings and require current order read+write for replay.
