# Výsledek lokální realizace platebního hardeningu

Lokální společné části i omezený Barion sandboxový adaptér jsou implementované.
Reálné platby, refundy a expirace prošly adaptérem, společným enginem a SQL ownerem
v disposable DB; viz [aktuální integrační receipt](BARION-INTEGRATION-RESULT-2026-11-06.md).
Ostrý provoz nadále vyžaduje account/chargeback/reversal a E1/E2 gates.
Žádné produkční SQL, nasazení, aktivace, ostrá platba, commit nebo push neproběhly.

Přesný HEAD, větev, digesty finálních vstupů a disposable DB identita jsou v
[result-inputs.json](result-inputs.json). Současný silně rozpracovaný workspace
byl zachován. Vstupní relevantní diff je v
[initial-payment-diff.patch](initial-payment-diff.patch).

## Ověřené brány

- Deno: **148 passed, 0 failed**, včetně nového machine endpointu, malformed RPC,
  izolace vadného konektoru, skutečné Stripe pagination/transport fixtures,
  timeout/retry a common engine adaptéru bez session lookup API.
- SQL: **39 souborů prošlo** na fresh disposable projektu
  `festapp-payment-provider-hardening`, port 55472. Zahrnuty payment providers,
  Stripe, payment lifecycle, setup a dotčené form settings.
- Populated upgrade: **1 passed, 0 skipped**. Před upgradem vznikly syntetické
  skutečná bankovní záloha přes existující lifecycle owner a přijatý SQL email
  receipt (testovaná simulace provider acceptance bez odesílání), ordered/paid/sent, partial/full refund, dispute, expired,
  aktivní lease, callback receipt a capability fixtures. Hashy celých tabulek
  orders/payment/tickets/history/movements/disputes/events/capabilities/
  decisions/email_messages se po migraci shodovaly. Žádná schema migrace
  neposlala email ani nepřepočítala historickou platbu.
- Dvouspojení concurrency: **1 passed, 0 skipped**; test obsahuje více skutečně
  překrytých scénářů checkout/webhook replay, uzavření prodeje, storno,
  refund/admission, výměnu příjemce a nový závod unresolved release/late webhook.
  Samostatná SQL matice aplikuje stejného ownera také nad odlišným testovacím
  provider úložištěm bez Stripe session modelu. Reálný druhý protokol tím ověřen není.
- Flutter: původní sada měla 97 případů; 94 prošlo a 3 assertions požadovaly
  starý Stripe klíč. Opravená očekávání kanonické mapy prošla v cíleném běhu
  všech 8 dotčených případů. Navíc **24 setup story případů prošlo**.
- Dart core: **9 passed**. Cílený Dart analyze nemá errors ani warnings;
  zůstává 66 info-level style/deprecation hlášení. Celkový architecture gate
  je stále červený kvůli **16 předexistujícím nezařazeným Flutter test roots**
  v jiných rozpracovaných oblastech; nová cross-module závislost byla opravena
  na veřejný barrel. Tato širší brána není označená za průchod.
- Web: **25 payment/controller/picker testů** a **6 callback bootstrap testů**
  prošlo. Hosting/CSP/PWA sada měla 17 průchodů mimo coverage; opravený coverage
  manifest prošel v celé své dvoutestové sadě. Coverage inventory: **50 production
  functions, 1 excluded, 0 uncovered**.
- Frozen connector/Stripe history, nový assembler `--check`, baseline contract
  a `git diff --check` prošly. DB byla po finálním běhu zastavena; ostatní
  projekty nebyly zastavovány. Flutter/Dart brána byla provedena sériově;
  jeden vlastní předčasně zahájený test byl přerušen při zjištění cizího buildu.

Přehled výsledkových výstupů a hashů původních logů:

## Úpravy předpokladů plánu a zbytkové brány

Prázdné Stripe list API není doložená silně konzistentní absence. Dosavadní
`noSessionVerified` z prázdného hledání proto nevzniká. Pokus zůstává v recovery;
po uplynutí uložené rezervace společný owner uvolní inventář a pozdní peníze
ponechá k explicitnímu dořešení. To platí i při pokračujícím stránkování.
Původní `STRIPE_PAID_TRANSITION_FAILED` diagnostika je zachována jen na vnějším
Stripe RPC adaptéru; finanční rozhodnutí zůstává společné.

Historický setup v režimu přípravy může zůstat bez bankovního účtu; okamžitý
nebo plánovaný placený prodej a explicitní výběr účtu se stále ověřují. Žádná
náhradní online brána se nedoplňuje automaticky.

Přihlášení, sandboxové schválení a CZK účet jsou vyřešené; podrobný
aktuální výsledek je v [navazující evidenci](BARION-APPROVAL-2026-11-06.md).
POSKey a ověřená identita peněženky jsou v lokální šifrované macOS Klíčence.
Synchronizace iCloudu není potvrzena. E1/E2, marketplace a výběr provizí
zůstávají uzavřené. Produkční rollout nebyl proveden.
