## Implemented

- Full-Dashboard, direct-charge Connect model, no platform fee/transfer. Unit-manager authorization, actor/tenant/unit/mode-bound OAuth state, verified replacement, pause/resume and durable disconnect with impact checks. Charges and payouts are distinct states. Replacement affects future orders and preserves historical account identity.
- Form-editor cards for **bank**, **Stripe**, or **both**, using existing Save/Discard drafts. Bank is the legacy default. Server availability and incompatibility reasons drive both clients; no bank account is required for Stripe. Deposits, surcharge, Fakturoid and unverified surfaces are rejected server-side.
- Canonical order/waitlist commands atomically attach an immutable attempt, hashed independent payment/return capabilities and encrypted delivery source. One active attempt, fixed 31-minute reservation, stable provider idempotency and receipted commands preserve the original order across retries.
- Hosted Checkout, raw-byte signed connected-account webhook ingestion, one economic ledger, common totals, full/partial refund handling, dispute hold/release, late-payment handling without capacity resurrection, existing email queue and send-time admission fences. Actual provider money is retained even when legacy/manual facts conflict; those cases require resolution.
- JS and Flutter method/amount/recipient review, exact currency precision, explicit fresh-catalog review preserving answers after price changes, protected pay/return pages and one-use embed handoff. View/return/handoff scopes never expose an order-pay bearer. Refund admission decisions are available in the existing ProductsDialog, with an audit note and selected unused tickets or explicit keep-admission choice.
- Online-only Stripe admission at canonical scanner writers, bank offline behavior preserved, Stripe excluded from native offline exports. Total/day reports retain provider occurrence dates and distinguish refunds/disputes/unattributed legacy external values.
- Bounded recovery, durable pagination for refunds and lost-Session lookup, account lifecycle checks, backoff, source retention, new-sales switch and prepared scheduler installer. No scheduler was activated. Public root `stripe` is reserved, with a migration preflight rejecting an existing conflicting occasion URL.

`payment_method` (bank/Stripe) is introduced by this work. It does not replace the pre-existing `payment_type` contract (deposit/full).
