Implementuj krátké náhodné 8znakové alfanumerické kódy URL pro automatické vytvoření a duplikaci událostí/formulářů (bez řetězení původního odkazu a suffixů), možnost ručně zadat popisný slug, úpravu a kopírování poslední uložené adresy, atomickou SQL rezervaci současných i historických slugů a canonicalizaci starých adres v JS i Flutteru. Starý slug nesmí převzít jiná položka; historie odkazuje přímo na stabilní ID. Zachovej query, osobní capability fragmenty, oprávnění, session formuláře a existující veřejné routy. Název kopie akce lokalizuj podle aktuálního jazyka uživatele při duplikaci: `(kopie)` pro češtinu a `(copy)` pro angličtinu; přenes locale přes skutečné command vstupy a výsledek ulož atomicky včetně správného auditního popisku. Kopie kopie má jediný suffix. Neprováděj plošné přejmenování existujících adres ani názvů.

Verification: standard. Postupuj podle závislostí vln plánu, bez zastávek a opakovaných review mezi vlnami. Po jednom krátkém sjednání kontraktu deleguj malou UI část na **GPT Astra Medium** (`gpt-6-astra`, `reasoning_effort: medium`, `fork_turns: none`); uživatel tento model a delegaci výslovně požaduje. UI agent promyslí a implementuje existující nastavení/tvorbu, uložený copy baseline, náhledy a locale předání, souběžně s tvou prací na backendu. Ty vlastníš SQL, migraci, command adaptéry a JS/Flutter canonicalizaci. Předem odděl vlastnictví souborů. Nespouštěj další nezávislé audity. Automatický create bez slugu řeší server při uložení, bez draft rezervačního RPC; uložený canonical link se vrací ze stávajícího commandu. Zahrň legacy, demo i setup-wizard copy cestu a zachovej locale při retry. Validace tvoří jednu společnou cílenou dávku po spojení, nezávislé sady mohou běžet souběžně; neopakuj již úspěšné nezměněné kontroly. Respektuj existující rozsáhlý rozpracovaný strom a nic cizího nevracej. Všechny skutečné SQL writery včetně sync commandů musí používat jedinou rezervační hranici bez persistentních aplikačních triggerů. Dle následného upřesnění vlastníka zachovej existující mezitenantové duplicity pomocí zmrazených tenant vazeb, bez přejmenování. Nové adresy musí být globálně jedinečné. Konflikt uvnitř tenantu nebo formulářového namespace zastavuje migraci. Zastaralé generátory veřejných slugů a obcházení registru odstraň, historii adres trvale ponech.

Pokud se premisa plánu ukáže nesprávná, aktualizuj plán konkrétním důkazem a uprav příslušnou vlnu. Nenechávej placeholdery, paralelní implementace ani další speculative fallbacky. Uživatelem požadovaná UI delegace nenahrazuje vlastnictví integračního výsledku hlavním implementátorem.

Ověř cílené SQL, JS a Flutter kontrakty podle plánu a repository pravidel. Bez další autorizace neprováděj produkční inventuru vyžadující přístup k živým datům, migraci, deployment, commit ani push. Handoff stručně uvede změněný kontrakt, převedené vstupy a odstraněné generátory, výsledky validace a přesné zbývající provozní kroky.
