## Canonical contract

- An active code resolves to exactly one occasion or grants no access. One `occasion_hidden` record can be referenced by at most one occasion; a validated global unique constraint enforces this independently of application code. Multiple NULL references remain valid for unconfigured events.
- `get_scanner_occasion_for_scan_code_internal` is the single live proof owner for modern and retained legacy boundaries. Empty, ambiguous and permanently retired credentials never grant access.
- `update_scan_code` owns authorized persistence; `get_or_create_scan_code` owns initialization/rotation and retries actual collisions. Both runtime allocation and the one-off repair use the same private cryptographic five-character sampler. Unique active-secret indexing and the private retirement registry prevent allocation of existing or retired values.
- Every successful rotation retires its previous value atomically. A failed collision leaves the losing event's credential usable. Previously shared values stay dead after deletion or detachment of copies.
- Event copying starts without scanner access. It cannot accidentally copy a credential even if its application implementation regresses, because the database rejects a second reference.
- Navigation is scoped to backend/generation/organization/occasion and canonical event link. The obsolete global return key and foreign returnTo values are ignored; scanner history and reload retain the chosen event.
