## Actual call graph and retained boundaries

- Auth: Edge register -> service-only enqueue_account_email -> create_user_from_registration -> pure identity writer + registration unit initializer. Manager create -> scoped profile/update_user parent -> internal invoker `_ws` -> same pure writer. Google, reception and group-import regression files passed. Token/scan owners remain separate proof-based contracts.
- News: DbNews -> NewsCommands -> existing command transport and mutation owner. `ClientSyncRuntime.isV1Selected` still selects read capability only. Non-sync notification-only `sendGroupNotification` retains the existing scoped `enqueue_notification_v1(bigint,text,text,jsonb,jsonb)` queue boundary; it does not write news or markers directly.
- Occasion readers: settings/copy/demo/inventory/schedule -> common context reader; public unit lists retain get_public_occasions; forms retain their dedicated link resolver and closed header contract. DbUnits count retains scoped table access.
- Groups: editor/import/map-editor -> existing bundles and commands; member profile -> get_user_groups + get_user_group_info_with_users, or private_profile. DbPlaces direct public reads remain for public map/timetable consumers under the narrowed policy; no new general place RPC was introduced.
- Templates: DbEmailTemplates -> existing SQL template owners. There is no new table fallback.

Exact retained tables, authorization, owners and removal conditions are in `database/functions/security/data_security_contracts.json`. Supported installed Android/iOS builds remain unproven. Repository release instructions identify the private manifest and Google Play gateway but do not establish which installed builds are supported. No gateway write/edit or mobile release was invoked. The final removal of the remaining safe SELECTs is pending that evidence. Old unsafe Auth bodies are not retained for compatibility.

Legacy NewsModel serialization does not persist individual isRead markers; sync private payloads retain the existing identity epoch and cache keys. Public catalogs and pending mutation receipts were not cleared or renamed. The new map join validates both identity and occasion, including an occasion captured before the async profile read.
