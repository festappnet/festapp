# Occasion setup preview follow-up

The appearance question now owns colors and fonts with a form preview. Font selection is always visible and preset samples resolve the actual loaded Google Fonts family, including runtime aliases. Loading failures provide an in-place retry. Selection indicators reserve space.

Tickets have their own question: enable/disable admission, choose from the canonical template catalog and optionally open the existing detailed editor. Admission follows visible form fields; products and seating remain independent. Gallery thumbnails use TicketLayoutPainter and the actual shared font resources. Shared styling preserves geometry, selects readable foreground for light palettes, and keeps QR backing white. Current custom tickets are shown separately and are not silently replaced by selecting their current card. Editing clears the preset marker and reloads current resources. Stock-template selection clears an inherited background so the displayed palette agrees with the persisted choice.

The old appearance step eagerly mounted TicketSettings and started an unrelated preview request on every style remount; this request was surfaced through the generic error toast. Appearance no longer mounts that loader. The dedicated ticket gallery flushes the draft first, loads once, and shows scoped failure/retry. The detail-editor action has preview loading disabled because the gallery owns thumbnails. Native regression tests enforce no eager request. The reported draft's style configuration and actual Edge resolve response were replayed read-only/local: transport, font decoding and all template painters succeeded. The original production toast was not independently reproduced from that snapshot, so no more specific original backend failure is asserted.

Email delivery and preview already share renderEmail/confirmationSubstitutions and destination template/wrapper resolution. The setup widget was stripping style attributes, style tags and images and inheriting the app font. Web now renders the unchanged server HTML in a sandboxed, noninteractive iframe, isolated from app CSS, with document-height observation. Native preserves authored HTML/styles through its existing HTML renderer. The draft projection adds active ticket/product configuration; free or paid sample content now follows the draft rather than invented sample products. No email is sent by verification.
