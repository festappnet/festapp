# Host build cache retention

The canonical backend's `festapp-build-cache-cleanup.timer` runs hourly with
up to ten minutes of jitter and catches up after downtime. It invokes
`/opt/festapp-maintenance/prune-build-cache.sh`, maintained in
`automation/hetzner-supabase/runtime/` with its service and timer units.

Only unused cache in the default Docker builder, last used more than 24 hours
ago, is eligible. BuildKit targets at most 512 MB cache and at least 8 GB free
disk. These are best-effort targets: active/recent cache and other disk usage
can prevent reaching them. The existing host disk alert remains unchanged.
This job never prunes application images, containers, volumes or backups and
does not restart Docker or the application. The job asserts the canonical host
and runtime database identity and takes its own nonblocking execution lock.

Install the script root-owned mode 0755 and both units root-owned mode 0644,
after reviewing and verifying their source digests. Run `bash -n` on the script
and `systemd-analyze verify` on the staged units before installation. Reload
systemd, enable/start the timer and run the service once. Verify its exit
status, timer enablement/next execution, installed digests, current disk metrics
and container state. No tenant overlay or application build is involved.

Inspect with `systemctl status festapp-build-cache-cleanup.timer` and
`journalctl -u festapp-build-cache-cleanup.service`. Disable future cleanup with
`systemctl disable --now festapp-build-cache-cleanup.timer`; cached build data
can be regenerated by subsequent builds. Retain the source and execution
receipt when disabling the job.
