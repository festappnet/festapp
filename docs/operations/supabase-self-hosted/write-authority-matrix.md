# Write-authority matrix — full-freeze cutover

Updated: 2026-09-02

Production cutover uses `full-freeze`. Journal hybrid is not authorized and is
not a prerequisite. The repository inventory is generated by
`automation/hetzner-supabase/merge/write-authority-inventory.mjs`; its private
JSON output is append-only evidence and is intentionally not checked in.

Static classification proves repository reachability coverage, not that a live
freeze is active. The pre-snapshot decision remains blocked until fresh private
evidence proves every control above, zero active mutating sessions on
`default`, `a` and `slunovrat`, and no unknown deployed or external writer.

## Direct DML boundary

Twelve files still contain direct-DML candidates. Nine are released client
compatibility paths, two are server-side Auth/e-mail bookkeeping, and one is a
disposable integration script. The previously omitted
`saved_program_commands.dart` fallback was found by the expanded scan and has
now been removed; a missing `set_saved_program` RPC fails visibly.

These candidates do not authorize hybrid operation. Already installed clients
cannot be rewritten, so the full freeze must make every old DML route fail
before the final snapshot. New code should not add another direct-DML path; a
new scanner result is part of the repository gate.

The existing `client_sync_v1` seam and its 41 hardened RPCs remain useful for
normal operation, but are not treated as complete global journal coverage.
Three-target SQL parity was closed on 2026-08-29; any subsequent schema or
contract change must again pass parity across both cloud sources and the
self-hosted target before cutover.

## Tenant and external writers

The tenant configuration inventory covers all 14 `origin/prod/*` refs. Its
checked-in policy distinguishes three missing configurations from unknown
tenants:

- `prod/ticketonline` is a closed path/query-preserving retirement boundary;
- `prod/avapp` still needs external Android-listing retirement evidence;
- `prod/slunovratopava` still needs legacy-origin/store retirement evidence.

Five broad source-`a` catalogue clients are explicitly assigned to the
`application` freeze lane. They remain live-evidence blockers until the actual
freeze; they are not required to adopt per-occasion journal flags.

Provider dashboards, payment/bank callbacks, DNS/hosting routes and credentials
are external reachability surfaces. They must be reconciled with current
deployment and traffic receipts; repository classification alone cannot close
them.

`runtime-writer-policy.json` is the fail-closed source list for all 20 Edge
Functions and three Worker entrypoints. It records their trigger and external
effects; repository preflight fails if a new runtime entrypoint is not added to
that policy.

Canonical code now verifies exact-topic AWS SNS Signature Version 2 ingress for
`bank-mail-parser` and uses a Vault-backed bearer contract for `notify`; the
legacy unauthenticated notification trigger is dropped until explicit canonical
setup. The `fetch-http-data` surface requires occasion-editor authorization and
rejects private DNS, unsafe redirects, non-images and oversized responses.
Provider Signature Version 2, Vault/Function secret equality and signed live
canaries remain operational activation gates.
`instance-install` is excluded from production rather than migrated because it
accepts database credentials and executes remotely fetched SQL.

## Gate contract

The final evidence consumed by `cutover-mode-gate.mjs` must report a complete
writer inventory, zero unknown writers, zero effective direct-DML bypasses,
every required freeze lane active and zero mutating sessions. “Known in source”
is not equivalent to “blocked in production”.
