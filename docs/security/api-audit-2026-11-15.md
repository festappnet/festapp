# API audit - 2026-11-15

V kontrolovaném rozsahu nebyl potvrzen únik dat ani obejití autentizace.
Audit potvrdil jednu funkční chybu při přetížení a jednu latentní chybu
společného HTTP adaptéru. Nejde o úplný penetrační test všech RPC a SQL oprávnění.
Zdroj: pracovní strom nad `ba97e57d7`, včetně již přítomných necommitnutých změn.
Produkční shoda celého pracovního stromu nebyla ověřována.

## Následné opravy

Oba nálezy byly následně opraveny v pracovním stromu podle
`docs/plans/api-audit-fixes-2026-11-15.md`. Níže je zachovaný původní stav
nálezů a auditní evidence. Samostatná reprodukce vadného chování byla
nahrazena regresními testy v `tools/festapp/test/api-transport.test.mjs`
a `tools/festapp/test/context.test.mjs`. Ty před opravou selhaly na F1 a F2.
Opravy dosud nebyly nasazené do produkce.
Na finálním zdroji je ověřeno 70 cílených testů bez přeskočení; detail běhů
a opravy starého citlivého očekávání počtu Auth volání je zaznamenán v plánu.

## F1 - střední: dočasné vyčerpání souběhu zakazuje opakování

`tools/festapp/src/remote/hosted-runner.mjs:37` odmítá třetí souběžný
požadavek stejného grantu přes `check(..., 'TEMPORARILY_LIMITED')`.
`OperationError` má ve výchozím stavu `retryable=false` a HTTP adaptér
tuto hodnotu přenese do odpovědi.

Reprodukce přes skutečný lokální HTTP server a OAuth: dva požadavky stejného
grantu byly pozdrženy na simulované upstream Auth hranici. Třetí dostal:

```json
{"status":429,"code":"TEMPORARILY_LIMITED","retryable":false,"outcome":"rejected"}
```

Chyběla i hlavička `Retry-After`. Po uvolnění oba požadavky i další pokus
vrátily 200. Klient respektující `retryable` tak může ukončit zpracování
obnovitelné chyby. Stejná větev obsluhuje celkový limit 16 aktivních požadavků.
Nejde o obejití limitu ani oprávnění.

Doporučení: vyhodit `OperationError('TEMPORARILY_LIMITED', true)`;
případný krátký backoff sladit s klientským retry kontraktem. Doplnit test
HTTP odpovědi a zotavení po uvolnění souběhu.

## F2 - nízká, latentní: platná prázdná upstream odpověď vyvolá TypeError

`tools/festapp/src/context/profile.mjs:136` vždy vytváří
`new Response(Buffer.concat(chunks), ...)`. Pro HTTP 204, 205 a 304 Fetch
nepovoluje tělo ani v podobě prázdného Bufferu. Reprodukce přes skutečný
`boundedFetch` s `Response(null, {status:204})` skončila `TypeError`.

Potvrzena je chyba helperu. Nebyl doložen konkrétní produkční endpoint,
který dnes touto cestou vrací 204, ani selhání produkční business operace.
Doporučení: pro bezobsahové statusy předat `null` a ověřit i běžnou JSON
odpověď a stávající limit velikosti.

## Provedené ověření

- 18 nízkofrekvenčních živých HTTP požadavků na `api.festapp.net` a
  `api.vstupenky.online`: manifesty a discovery 200; chybějící a neplatné
  přihlašovací údaje 401; poškozený JSON 400; chybná metoda 405 s `Allow: POST`;
  nesprávný Content-Type 415; tělo nad limitem 413. Cizí Origin a jeho preflight
  dostaly 403. Soukromé/chybové odpovědi měly `Cache-Control: no-store`.
- 57 testů API transportu, kontraktu, storage, rate limitů a webhook transportu:
  všechny prošly, žádný přeskočený. Zahrnují skutečný lokální OAuth/HTTP,
  oddělení API audiences a MCP, revokaci, DPoP podpisy/replay/downgrade,
  refresh a syntetický PDF renderer. Upstream Auth/business odpovědi jsou fixture.
- 84 testů skutečných registrovaných Edge handlerů prošlo bez selhání;
  pokrývají zejména vstupní validaci a odmítnutí neoprávněného vstupu před I/O.
  Neprokazují všechny úspěšné business průchody.
- Dvě samostatné reprodukce potvrdily F1 a F2.

platné bezobsahové statusy, JSON a zachování limitu velikosti odpovědi.

## Meze závěru

V produkci nebyl použit platný uživatelský grant, měněna data ani vyvolány
platby či emaily. Nebyl proveden zátěžový test, nový audit živých SQL ACL/RLS
ani kompletní izolovaná PostgreSQL sada. Úspěšné přihlášené průchody byly
ověřeny lokálně proti simulované upstream identitě. Zákaz cizího Originu je
současná politika serveru, nikoli sám o sobě bezpečnostní chyba; browserová
integrace z jiné domény takto přímo fungovat nebude.

Samotný audit neměnil aplikační zdroj. Následná implementace oprav změnila
pouze popsané dvě cesty a jejich testy; do původních rozpracovaných změn
nezasáhla a nic nenasazovala.
