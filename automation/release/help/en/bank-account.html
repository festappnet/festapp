Manage the receiving account at organizer level. Creating a bank account, connecting it to the bank and checking which account a form uses are separate tasks.

Who can manage the account?

Sign in to administration and open the correct organizer unit. Creating an account requires unit manager permission. Managing an existing account requires both account administrator permission and management access to a unit actually linked to it. Ask the responsible manager if the section is unavailable.

Create or link an account

  1. Open Bank Accounts

    Choose Bank Accounts in organizer administration. This is separate from an individual event's Settings tab.{{APP_LINK:bank-accounts}}

  2. Choose the operation

    Select Add Bank Account. Use Create New Account for a new account record, or Link Existing Account when you already have the required access. Avoid duplicate records of the same account.

  3. Enter general details

    On General, enter a label and choose the account format. For a Czech account, you can enter the account number and bank code. For a Slovak account, enter the account number and choose a Slovak bank or enter its code. The IBAN is generated automatically and new accounts default to EUR. If your bank already gave you an IBAN, choose IBAN to paste it directly. Check the currencies and add the beneficiary name for payment instructions if needed.

  4. Save and check the list

    Verify the saved identity and currencies. Account priority affects currency routing; check which account is primary and which ones are backups.

Connect the bank separately

An account in the list does not prove that transactions are being imported. Open its bank connection. For Fio, follow the API token guide. Where supported, configure incoming-payment email notifications using the receiving address shown for this account and check connection status.

Save the token only in the matching bank account's connection settings. It does not belong in a public form, order note or event setup wizard.

Check the account used for sales

For a new event, select the prepared account in the wizard. Open the form’s Settings → Payment details and choose Account for bank transfers. Select an account supporting all form currencies, or keep By organization order to use the first account supporting each payment currency. Then check the form's payment settings. Verify the account and currency in the buyer's payment instructions before sharing the form.{{APP_LINK:forms}}

In Bank Accounts, drag the account by its handle or use its up and down arrows to change the order. A star marks the default account for each currency. If someone changes the order while you are editing it, check the refreshed list before trying again.

When the real account changes

Create a separate record for a different physical account and use it for future sales. Do not reassign historical bank transactions by replacing a connected account's identity. Unlinking an account from a unit does not delete the account, resolve existing orders or refund money.

Find a transfer with an incorrect reference

Follow manual payment matching. You need bank transaction management and event order editing permissions.

Confirm email payments

Choose Confirm and pair or Dismiss observation on the notification card. Each opens a dialog over the account settings.

Email notifications alone never pay orders. Open the account connection and its email queue (pending email observations remain accessible even after switching the account to API mode), and compare the amount, currency, reference, counter-account, bank date and message with internet banking. Select an order, tick the banking verification checkbox and choose Confirm and pair. Suggestions recognise variable symbols and RF references, including references in the message. Use Find order to search by variable symbol (including formats such as VS 123 or vs:123), RF reference or public order number. The list shows the order, customer, the order's variable symbol, status and remaining balance. When the payment has a valid variable symbol, the list indicates whether the symbols match. You can find editable non-demo orders for the selected account and currency with a balance due. This includes paid or sent orders with a deposit and a remaining balance. A different amount is marked and can represent a partial payment.

Confirmation requires account administrator permission, management of a linked non-demo organizer unit and order editing permission for the selected event. The same checks apply to lookup; account aliases also require administration of the canonical account. Readonly users have no confirmation or dismissal actions. Closing new bank sales does not prevent confirming an already received transfer.

The pending email tile in API mode appears only when email observations remain. API-origin quarantined movements cannot be confirmed as email payments. Exact API or legacy matches that appear after loading offer dismissal and already-recorded information, without a separate-payment checkbox. Use Load more for the next page. Use Dismiss observation for an irrelevant or duplicate notification and enter a reason; this is audited and never credits money. Exact duplicates of an existing API or legacy bank movement are automatically resolved with a link to the original transaction (if that transaction is currently unpaired, the interface tells you so). Possible duplicates — including observations matching another confirmed email — are never hidden automatically: they remain in the queue with the related transactions for comparison, so you can either dismiss the observation or explicitly confirm it as a separate payment with Confirm anyway — this is a separate payment (audited). A later API bank movement adopts a confirmed email when its normalised facts match uniquely. When it is only a possible duplicate (for example a counter-account or ±1 bank day difference, or multiple candidates), the movement is still recorded in the bank transaction ledger without automatic pairing so real money is never trapped and nothing double-credits; if it is a separate payment, pair it manually in the payment overview. Use the existing order payment overview to unpair or reassign a confirmed payment; the original banking verification remains in the audit.
