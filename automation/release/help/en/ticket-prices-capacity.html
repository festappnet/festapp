Set clear ticket variants, prices and availability. Your limits must match what you can actually sell.

Before you begin

You need a form and permission to edit its offer. Prepare variant names, prices, currencies and quantities. Decide which variants share the same physical capacity.

Prepare products and prices

  1. Open the form offer

    A product type groups related choices, such as admission or dinner. A product is one priced choice, such as standard admission or a vegetarian dinner.{{APP_LINK:products}}

  2. Add the choices

    Use Add Product Type and Add Product. Enter a clear name, price and currency. A zero price means a free option, not zero availability.

  3. Check selection rules

    Choose whether selection is required and whether multiple choices are allowed. Enable Show only for options you want to offer. Check any preselected choice.

{{MEDIA:en/forms/editor}}

Set the available quantity

Set a quantity or capacity for limited products. Where the field explicitly says that zero means unlimited, do not use zero to close sales; use visibility or availability instead. Do not apply this rule to a standing area's seat count.

When different price variants consume the same stock, put them in the same capacity group. Two separate limits of 100 do not create one shared limit of 100. For assigned seating, also check each seat's product binding.

Changes during sales

Save price or availability changes and check the public form. Changing the offer does not automatically rewrite existing order prices. Open the existing order detail, choose Tickets and places and edit the item. Recheck the balance. Use scheduled price changes only when a change is intended for a specific future time. For an existing purchase, follow changing an order.{{APP_LINK:orders}}

Verify the result

Check every visible option, currency and total in a private window. Availability can depend on the sales period, shared capacity and current holds. Check existing reservations before increasing limits to resolve an unavailable option. Check the sales period and availability in Forms.{{APP_LINK:forms}}

Discount codes

Prepared feature: these instructions describe the forthcoming discount code version. Production deployment and activation have not been performed.

  1. Enable the event extra feature

    Enable Discount codes in event settings and save. The feature is off by default and is independent of payment plans.{{APP_LINK:settings}}

  2. Create a code alongside products

    Open Discount codes in product administration, then Create code. Use 4-32 ASCII letters, digits or hyphens, for example DANCE10. Letter case is ignored. A used code cannot be renamed.{{APP_LINK:products}}

  3. Set the discount and scope

    Choose Percentage discount (%) or Fixed discount. Fixed discounts have one currency and cannot be used for orders in a different currency. Expand Forms and Products to restrict the scope. An empty selection includes all applicable forms or products in the event. Discounts use current prices at purchase confirmation, including scheduled price waves.

  4. Set validity and usage

    Choose the local dates and times for Valid from and Valid until. The end instant is excluded. The Order limit counts successfully created orders, not individual tickets. Leave it empty for no limit. Enable Active and Save. New codes start inactive.

The list shows uses and total discounts granted by currency. To pause a code, open it, turn Active off and save. Disabling the event extra feature stops new uses, including direct API requests, while preserving definitions, history, uses and prices already granted. Re-enabling does not reset limits.

Purchase and amendment limits

One code per order. Codes cannot be combined or added after purchase. Platform fees and visual-only surcharges are ineligible. Actual deposits are never reduced: if a product's net price would be less than or equal to its positive deposit, the code is rejected for that selection. A zero-price order without a deposit requires no payment.

Joining a waiting list does not use a code. Enter it when accepting an offer. Each separate partial acceptance creates an order and requires a new explicit code. Preprinted ticket batches do not accept codes.

Discounted orders still support contact and nonfinancial answer corrections, delivery, cancellation and supported refunds. This version rejects product changes, repricing and seat swaps. Cancellation, expiry and refunds do not restore uses. Refunds are based on the net amount actually paid. The original discount snapshot survives cancellation.
