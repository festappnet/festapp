# Host measurement preset

Use `festapp-host-gtm.json` in the organizer website's **web GTM container**, where
its native GA4/Google Ads/Meta tags and CMP already run. New WordPress, Joomla and
Wix embeds default to host measurement. Existing saved destination choices stay
unchanged. The Unit runtime remains an independent destination; this preset does
not copy cookies or promise a cross-site GA session.

1. Back up the website container. Import into a new workspace using **Merge**,
   review every dependency and resolve name collisions. Never overwrite the
   published container. All four imported tags are paused.
2. Replace both GA4 tags' measurement IDs and Ads conversion ID/label placeholders with
   the website's destinations. Keep the existing native Google tag/conversion
   linker configured for the website; do not add a second native page-view tag.
   Select the same destinations as the website if its attribution is required.
3. The CMP must establish denied defaults before tags and issue Consent Mode v2
   updates after a saved choice. GA4 requires `analytics_storage`; Ads and Meta
   require all of `ad_storage`, `ad_user_data`, `ad_personalization`. These added
   gates intentionally suppress tags while permission is missing, including
   cookieless events. Website events continue under their existing configuration.
4. Ads enhanced conversions use the native User-Provided Data variable in CODE
   mode, reading only Festapp's bounded `user_data` (email/phone) on purchase.
   Configure eligibility and customer-data terms in the merchant's Google Ads
   account before enabling it. No DOM contact detection or automatic data
   capabilities are enabled by this preset. Do not include that variable in GA4,
   Meta, logs or unrelated events. The embed clears contact data after its push.
5. Meta requires the website's existing initialized `fbq`. The paused Custom HTML
   tag sends allowlisted public ecommerce fields, with the purchase transaction
   ID as eventID; it never loads a pixel or reads contact data. Review its source
   against your own pixel configuration. Native website automatic matching is
   outside this preset; enabling it is the merchant's separate decision.
6. In GTM Preview, verify consent denied/granted/withdrawn, native website and
   embedded form events, one purchase per order, value/currency/order ID, and
   absence of contacts from GA4/Meta. Every imported trigger requires
   `form_embedded == true` and one explicit Festapp event. `form_page_view`
   stays a distinct GA4 event so it does not duplicate the website's `page_view`.
   Remove/disable overlapping existing conversion tags before enabling these.
7. Unpause only the reviewed destinations, preview again and publish through the
   merchant's normal process. Import success alone does not prove attribution:
   verify source/medium/campaign and conversions in the actual destination
   using an approved test campaign and real consent transitions.

The preset is generated by `node integrations/measurement/build_gtm_preset.mjs`.
Its native parameter shapes come from an actual GTM web workspace export;
`--check` checks deterministic generation. No account identifiers, credentials,
container settings, published versions or auto-detection settings are bundled.
